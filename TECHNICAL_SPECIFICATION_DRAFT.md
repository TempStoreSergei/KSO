# Проект Технического Задания (Черновик)
## Приложение-терминал для бронирования "Motel"

---

### 1. Введение
#### 1.1. Назначение документа
Настоящий документ описывает технические и функциональные требования к приложению "Motel" — программному обеспечению для стационарных терминалов (планшетов), предназначенному для автоматизации процесса бронирования номеров и услуг.

#### 1.2. Область применения
Приложение предназначено для использования персоналом и гостями в лобби мотелей, хостелов или отелей для быстрого оформления заселения.

#### 1.3. Целевая аудитория
- **Основные пользователи:** Сотрудники ресепшн, менеджеры.
- **Вторичные пользователи:** Гости (для самостоятельного оформления).

---

### 2. Общие требования
#### 2.1. Платформа и технология
- **Фреймворк:** Flutter.
- **Язык программирования:** Dart.
- **Целевые платформы:** В первую очередь, планшеты на базе Android и iOS. Также должна сохраняться возможность сборки под desktop-платформы (Windows, macOS, Linux).

#### 2.2. Стиль интерфейса
- Визуальный стиль должен соответствовать гайдлайнам **Cupertino (Apple iOS)** для обеспечения чистого и интуитивно понятного вида.

#### 2.3. Локализация
- Основной язык интерфейса: **Русский**. Все текстовые элементы, форматы дат и чисел должны соответствовать русскому языку.

---

### 3. Функциональные требования
#### 3.1. Модуль безопасности и доступа
- **FR-1: Экран блокировки**
  - Приложение должно запускаться с экрана блокировки.
  - Экран должен отображать текущее время и дату.
  - Разблокировка должна осуществляться с помощью жеста "slide-to-unlock" (потянуть для разблокировки).
- **FR-2: Динамический фон экрана блокировки**
  - Приложение должно загружать с сервера фоновые изображения для экрана блокировки.
  - Должна быть реализована функция слайд-шоу с настраиваемыми интервалами смены изображений.
  - Настройки (включено/выключено, интервалы) должны загружаться с бэкенда.
- **FR-3: Вход для администратора**
  - Должен быть реализован скрытый механизм доступа к экрану входа администратора.
  - Механизм: 5-кратное быстрое нажатие на виджет часов на экране блокировки.
  - После успешной активации должен открываться экран `AdminLoginScreen`.
- **FR-4: Автоматическая блокировка (Опционально, изменено)**
  - При бездействии пользователя в течение `N` секунд на экране бронирования, должно появляться модальное окно "Вы еще здесь?".
  - Окно содержит одну кнопку "Да". При нажатии на нее таймер бездействия сбрасывается.
  - Если в течение 60 секунд на модальное окно не было реакции, приложение должно автоматически возвращаться на экран блокировки.

#### 3.2. Модуль бронирования
- **FR-5: Пошаговый мастер бронирования**
  - Процесс бронирования должен быть реализован в виде пошагового мастера (`Stepper`).
  - Пользователь должен иметь возможность переходить на предыдущий шаг или отменить бронирование на любом этапе.
- **FR-6: Шаги мастера бронирования**
  1.  **Выбор корпуса:** Отображение списка доступных корпусов.
  2.  **Выбор типа номера:** Фильтрация и отображение типов номеров в выбранном корпусе.
  3.  **Выбор номера/места:** Визуальное представление или список доступных номеров/мест.
  4.  **Ввод данных гостя:** Форма для ввода ФИО. Должна использоваться кастомизированная экранная клавиатура.
  5.  **Выбор категории:** Выбор категории бронирования (например, "Стандарт", "Онлайн-бронь").
  6.  **Выбор периода:** Календарь для выбора дат заезда и выезда.
  7.  **Выбор доп. услуг:** Список доступных услуг/товаров для добавления к заказу.
  8.  **Выбор способа оплаты:** Отображение доступных методов оплаты (например, "СБП", "Картой").
  9.  **Подтверждение:** Сводная информация по бронированию для финальной проверки.
  10. **Исполнение платежа:** Экран ожидания подтверждения платежа.
  11. **Результат:** Экран успешного завершения или ошибки.
- **FR-7: Экранная клавиатура**
  - Для полей ввода должна использоваться кастомная экранная клавиатура, адаптированная для кириллицы и цифрового ввода.

#### 3.3. Модуль взаимодействия с бэкендом
- **FR-8: API-клиент**
  - Все HTTP-запросы к бэкенду должны проходить через единый сервис `ApiClient`.
  - Клиент должен управлять сессиями (например, через `cookie_jar`).
- **FR-9: WebSocket-клиент**
  - Для получения обновлений в реальном времени (статус платежа) должен использоваться `WebSocketService`.
  - Сервис должен уметь устанавливать соединение, подписываться на события и разрывать соединение.

---

### 4. Требования к API (ожидаемые эндпоинты)
- `GET /screensaver/get_settings`: Получение настроек для экрана блокировки.
- `GET /screensaver/get_files`: Получение списка файлов (изображений) для слайд-шоу.
- `GET /api/buildings`: Получение списка корпусов.
- `GET /api/room_types?building_id={id}`: Получение типов номеров для корпуса.
- `GET /api/rooms?type_id={id}`: Получение списка номеров.
- `GET /api/categories`: Получение списка категорий бронирования.
- `GET /api/items?category_id={id}`: Получение списка доп. услуг.
- `POST /api/bookings`: Создание нового бронирования.
- `WebSocket /ws/payment/{booking_id}`: Канал для получения статуса платежа по WebSocket.

---

### 5. Нефункциональные требования
- **NF-1: Производительность**
  - Анимации перехода между шагами должны быть плавными (60 FPS).
  - Время ответа от API не должно блокировать интерфейс; должны использоваться индикаторы загрузки.
- **NF-2: Надежность**
  - Приложение должно корректно обрабатывать ошибки API (например, отсутствие сети, ошибка 500) и отображать пользователю понятные сообщения.
  - Приложение должно стабильно работать в режиме 24/7.
- **NF-3: Безопасность**
  - Данные для доступа к API (если таковые имеются, например, токены) не должны храниться в открытом виде.
- **NF-4: Юзабилити**
  - Интерфейс должен быть оптимизирован для сенсорного ввода на планшетах.
  - Все интерактивные элементы должны быть достаточно крупными и легко нажимаемыми.

---
### 6. Исключено из области действия (Out of Scope)
- Панель администратора для управления настройками, номерами и пользователями (предполагается, что она существует в виде отдельного веб-интерфейса).
- Поддержка других языков, кроме русского.
- Офлайн-режим работы.
