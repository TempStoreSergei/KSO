# Описание файлов проекта "Motel"

Этот документ содержит подробное описание всех файлов с исходным кодом (`.dart`) в папке `lib`, сгруппированных по их функциональному назначению.

## 1. Пользовательские экраны и компоненты

Эта группа включает в себя все файлы, отвечающие за интерфейс, с которым взаимодействует конечный пользователь (сотрудник или гость).

| Файл | Описание |
| --- | --- |
| `presentation/lock_screen/lock_screen.dart` | **Экран блокировки.** Это первый экран приложения, который видит пользователь. Он отображает фоновое слайд-шоу, загружаемое с сервера, текущее время и дату. Реализует механику разблокировки "slide-to-unlock" для перехода к экрану бронирования, а также скрытый жест (многократное нажатие на часы) для входа в административный раздел. |
| `presentation/booking/room_booking_screen.dart` | **Главный экран бронирования.** Ключевой экран приложения, организующий пошаговый процесс создания бронирования. Он управляет состоянием всего процесса через `BookingCubit`, динамически отображая нужный виджет для каждого шага. Также отвечает за логику автоблокировки при бездействии. |
| `presentation/booking/widgets/booking_sidebar.dart` | **Боковая панель этапов бронирования.** Виджет, который наглядно показывает все шаги процесса бронирования, отмечая текущий, пройденные и будущие этапы. Помогает пользователю ориентироваться в процессе. |
| `presentation/booking/widgets/step_building_selection.dart` | **Шаг 1: Выбор корпуса.** Компонент, отображающий список доступных корпусов для начала процесса бронирования. |
| `presentation/booking/widgets/step_room_type_selection.dart` | **Шаг 2: Выбор типа комнаты.** Компонент, позволяющий пользователю выбрать тип комнаты (например, 4-х местная, 6-ти местная), что влияет на дальнейшие шаги. |
| `presentation/booking/widgets/step_room_selection.dart` | **Шаг 3: Выбор комнаты и места.** Двухэтапный компонент: сначала пользователь выбирает номер комнаты из списка, а затем — конкретное койко-место в этой комнате. |
| `presentation/booking/widgets/step_guest_info.dart` | **Шаг 4: Ввод данных гостя.** Форма для ввода ФИО гостя. Поля ввода интегрированы с кастомной экранной клавиатурой. |
| `presentation/booking/widgets/step_category_selection.dart` | **Шаг 5: Выбор категории.** Компонент для выбора категории операции: "Проживание", "Услуги" или различные типы "Штрафов". |
| `presentation/booking/widgets/step_period.dart` | **Шаг 6: Выбор периода.** Кастомный виджет календаря для выбора дат заезда и выезда. Автоматически рассчитывает и отображает количество ночей. |
| `presentation/booking/widgets/step_item_selection.dart` | **Шаг 7: Выбор услуг/штрафов.** Компонент для выбора дополнительных услуг (при проживании) или конкретных штрафов. Позволяет указывать количество для исчисляемых позиций. |
| `presentation/booking/widgets/step_payment.dart` | **Шаг 8: Выбор способа оплаты.** Отображает итоговую сумму и позволяет выбрать один из способов оплаты: СБП, банковская карта или наличные. |
| `presentation/booking/widgets/step_confirmation.dart` | **Шаг 9: Подтверждение бронирования.** Финальный экран перед оплатой, где собрана вся информация о бронировании для проверки пользователем. |
| `presentation/booking/widgets/step_payment_execution.dart` | **Шаг 10: Проведение платежа.** Экран, который отображается во время оплаты. Показывает QR-код для СБП или инструкции для других методов. Имеет таймер обратного отсчета и слушает события от `WebSocketService` для получения статуса платежа в реальном времени. |
| `presentation/booking/widgets/step_success.dart` | **Шаг 11: Успешная оплата.** Простой экран, информирующий об успешном завершении операции. Автоматически возвращает на экран блокировки через 10 секунд. |
| `presentation/booking/widgets/step_payment_error.dart` | **Шаг 12: Ошибка оплаты.** Экран, который отображается в случае неудачной оплаты. Предлагает пользователю попробовать снова. |
| `presentation/guest_info/custom_keyboard.dart` | **Кастомная экранная клавиатура.** Виджет, реализующий полнофункциональную экранную клавиатуру с русской и английской раскладками, поддержкой верхнего регистра и спецсимволов. |
| `presentation/guest_info/numpad_keyboard.dart` | **Цифровая экранная клавиатура.** Упрощенная версия клавиатуры только для ввода цифр. |
| `presentation/booking/managers/inactivity_manager.dart` | **Менеджер бездействия.** Простой класс-обертка над `Timer`, который отслеживает отсутствие действий пользователя и вызывает колбэк по истечении времени. |
| `presentation/booking/managers/keyboard_manager.dart` | **Менеджер клавиатуры.** Управляет состоянием нескольких полей ввода (`TextEditingController`) и их фокусом (`FocusNode`), связывая их с кастомной клавиатурой. |
| `presentation/helpers/*.dart` | **Вспомогательные UI-компоненты.** Набор виджетов для создания консистентного UI: `GlassmorphicContainer` (эффект стекла), `AppBackground` (анимированный фон), `AdaptiveText` (масштабирование текста) и др. |
| `presentation/booking/widgets/step_container.dart` | **Контейнер для шага бронирования.** Общий шаблон для всех виджетов-шагов, который включает заголовок, подзаголовок и иконку, обеспечивая единый стиль. |

## 2. Административные экраны

Эта группа содержит экраны и компоненты, предназначенные для настройки и управления системой. Доступ к ним осуществляется через `AdminLoginScreen`.

| Файл | Описание |
| --- | --- |
| `presentation/admin_login/admin_login_screen.dart` | **Экран входа для администратора.** Предоставляет форму для ввода логина и пароля администратора. Использует кастомную клавиатуру и `LoginAdmin` use case для аутентификации. |
| `presentation/settings/settings_screen.dart` | **Главный экран настроек (Dashboard).** Центральный узел для навигации по всем административным разделам. Представлен в виде сгруппированного списка (`CupertinoListSection`). |
| `presentation/settings/acquiring/acquiring_settings_screen.dart` | **Настройки эквайринга.** Экран для управления физическим терминалом оплаты. Позволяет проверять соединение, запускать тестовые платежи, делать возвраты и открывать сервисное меню терминала. |
| `presentation/settings/bill_acceptor/bill_acceptor_settings_screen.dart` | **Настройки купюроприемника.** Интерфейс для управления устройством приема наличных. Позволяет смотреть статус заполненности, устанавливать лимиты, проводить инкассацию и запускать тестовый прием купюр. |
| `presentation/settings/bill_dispenser/bill_dispenser_settings_screen.dart` | **Настройки диспенсера купюр.** Экран для управления устройством выдачи сдачи. Позволяет настраивать номиналы в кассетах, пополнять их, проводить инкассацию и запускать тестовую выдачу. |
| `presentation/settings/fines/fines_settings_screen.dart` | **Настройки штрафов.** CRUD-интерфейс для управления списком штрафов. Позволяет создавать, редактировать и удалять штрафы, которые затем можно выбрать в процессе бронирования. |
| `presentation/settings/services/services_settings_screen.dart` | **Настройки услуг.** CRUD-интерфейс для управления списком дополнительных услуг. Позволяет создавать и редактировать услуги, их цены и параметры (например, является ли услуга исчисляемой). |
| `presentation/settings/room_prices/room_prices_settings_screen.dart` | **Настройки цен на проживание.** Экран для управления ценами на номера. Ключевая функциональность — экспорт текущих цен в CSV-файл и импорт обновленных цен из CSV-файла. |
| `presentation/settings/screensaver/screensaver_settings_screen.dart` | **Настройки заставки.** Позволяет администратору управлять слайд-шоу на экране блокировки: включать/выключать его, настраивать время до активации, загружать новые изображения, удалять старые и менять их порядок с помощью drag-and-drop. |
| `presentation/settings/shift/shift_settings_screen.dart` | **Настройки смен.** Экран для ручного управления фискальными сменами. Позволяет принудительно открыть или закрыть смену, переопределяя автоматическую логику `ShiftService`. |
| `presentation/settings/telegram/telegram_settings_screen.dart` | **Настройки Telegram-уведомлений.** Экран для настройки интеграции с Telegram. Администратор может ввести токен бота и ID чата для получения уведомлений о системных событиях. |
| `presentation/settings/transactions/transactions_screen.dart` | **Экран транзакций.** Отображает историю всех проведенных операций. Показывает ключевую информацию по каждой транзакции и ее статус синхронизации с 1С. Позволяет экспортировать все транзакции в ZIP-архив. |
| `presentation/settings/transactions/transaction_detail_screen.dart` | **Детали транзакции.** Показывает всю подробную информацию о конкретной транзакции, включая состав услуг, данные гостя и комнаты. Отсюда же можно инициировать отправку данных в 1С. |
| `presentation/settings/transactions/transaction_edit_screen.dart` | **Редактирование транзакции.** Форма для изменения данных гостя и комнаты уже существующей транзакции. |
| `presentation/settings/password/change_password_screen.dart` | **Смена пароля.** Форма для смены пароля администратора. |
| `presentation/settings/about/about_screen.dart` | **Экран "О приложении".** Отображает базовую информацию о приложении, такую как версия. |
| `presentation/settings/metrics/metrics_screen.dart` | **Экран метрик.** Отображает ключевые показатели производительности и использования приложения, полученные от `MetricsService`. |
| `presentation/settings/**/*.dart` | **Прочие файлы настроек.** Включают в себя все вспомогательные виджеты, `Cubit` и `State` классы, а также модели, используемые для построения экранов настроек. |

## 3. Ядро и общая логика

Эта категория объединяет файлы, которые составляют архитектурную основу приложения. Они не являются UI-компонентами, но обеспечивают их работу: бизнес-логику, взаимодействие с API, управление состоянием и модели данных.

| Файл | Описание |
| --- | --- |
| `main.dart` | **Точка входа в приложение.** Инициализирует глобальные сервисы (локализация, переменные окружения) и запускает корневой виджет `CupertinoApp`, устанавливая `LockScreen` в качестве домашнего экрана. |
| `core/api/api_client.dart` | **API-клиент.** Singleton-сервис, централизующий все HTTP-взаимодействия с бэкендом. Управляет сессиями через cookies, автоматически формирует запросы и обрабатывает ответы, преобразуя статусы ошибок в типизированные исключения (`ApiException`). |
| `core/services/websocket_service.dart` | **WebSocket-сервис.** Singleton-сервис для управления WebSocket-соединением. Используется для получения данных в реальном времени, в первую очередь — статуса платежа на экране `StepPaymentExecution`. |
| `core/services/shift_service.dart` | **Сервис управления сменами.** Реализует логику автоматического управления фискальными сменами. Содержит "умный" таймер, который планирует закрытие смены в конце дня, а также методы для ручного управления. |
| `core/services/metrics_service.dart` | **Сервис метрик.** Отвечает за сбор и локальное хранение (через `shared_preferences`) простой статистики использования приложения, например, количества успешных платежей. |
| `core/services/token_service.dart` | **Сервис токенов.** Управляет жизненным циклом токена аутентификации, сохраняя, извлекая и удаляя его из `shared_preferences`. |
| `presentation/booking/cubit/booking_cubit.dart` | **Cubit процесса бронирования.** Ключевой класс для управления состоянием (`State Management`) всего пошагового процесса бронирования. Содержит всю UI-логику: какой шаг показать, можно ли перейти к следующему, как обновить данные бронирования. |
| `presentation/booking/cubit/booking_state.dart` | **Состояние процесса бронирования.** Определяет структуру данных, которой управляет `BookingCubit`. Включает в себя текущий шаг, статус загрузки и все данные, вводимые пользователем (`BookingData`). |
| `domain/models/*.dart` | **Модели данных домена.** Определяют основные бизнес-сущности приложения (`BookingData`, `Fine`, `ShiftStatus` и др.). Это "чистые" классы данных, не зависящие от способа их получения или отображения. |
| `domain/entities/*.dart` | **Сущности домена.** Аналогичны моделям, представляют собой чистые бизнес-объекты (`ServiceEntity`, `Transaction`, `ScreensaverFile`). |
| `domain/repositories/*.dart` | **Абстрактные репозитории (контракты).** Определяют интерфейсы для работы с данными (например, `AdminAuthRepository`, `ServiceRepository`). Это ключевой элемент "Чистой архитектуры", отделяющий бизнес-логику от деталей реализации источников данных. |
| `data/repositories/*_impl.dart` | **Реализации репозиториев.** Конкретные классы, реализующие контракты из `domain/repositories`. Они выступают в роли моста между `DataSource` (источником данных) и `UseCase` (бизнес-логикой). |
| `data/datasources/*.dart` | **Источники данных.** Абстракции и их реализации для непосредственного взаимодействия с API через `ApiClient`. Это самый нижний уровень получения данных. |
| `domain/usecases/*.dart` | **Use Cases (Сценарии использования).** Инкапсулируют одну конкретную бизнес-операцию (например, `LoginAdmin`, `GetRooms`, `SaveTransactionUseCase`). Они вызываются из слоя представления (Cubit'ами) и используют репозитории для получения или отправки данных. |
| `core/api/api_exceptions.dart` | **Пользовательские исключения API.** Набор классов исключений, которые `ApiClient` генерирует при ошибках сети или сервера. Это позволяет более точно обрабатывать ошибки в вышестоящих слоях. |
